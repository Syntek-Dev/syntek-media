# Security Policy

## What this repository is

`syntek-media` is a **Copier template** that adds audio and video production to a repository,
usually a project generated by syntek-author. It runs no service, hosts no data and has no users of
its own. It does, however, run code on the owner's machine: Copier runs its tasks and migrations
under `--trust` when a project is generated or updated, and the project it generates holds a
toolkit, permission settings, skills and rules that run in the owner's repository and coding
sessions, some of them able to spend the owner's ElevenLabs credits.

The risk we most want to hear about is a defect, an unsafe default or a malicious change in that
code, reaching every project generated or updated from the template: a permission rule that lets a
paid call run without its prompt, a toolkit command that reads or writes outside the project, or a
migration that touches more than it says.

## Supported versions

| Version | Supported |
|---|---|
| The latest release | Yes |
| Any earlier release | No |

The latest release is the newest entry on the
[releases page](https://github.com/Syntek-Dev/syntek-media/releases), and its number is in
[`VERSION`](VERSION) on `main`. A project records the release it was generated or last updated from
as `_commit` in `.copier-answers.syntek-media.yml`. There are no maintained release branches: a fix
ships in a new release, and a project takes it with `copier update` (always with
`-a .copier-answers.syntek-media.yml`, as the README's
[Updating a project](README.md#updating-a-project) shows).

## Reporting a vulnerability

**Never report a vulnerability in a public issue, discussion or pull request.**

Report it only through GitHub's private vulnerability reporting:
[open a private report](https://github.com/Syntek-Dev/syntek-media/security/advisories/new) (or
go to the **Security** tab and choose **Report a vulnerability**). The report is visible only to
you and the maintainers.

Please include:

- the file, script or default at fault, with its path;
- the template version you looked at (a release tag, or `_commit` from the answers file);
- the answers that matter, such as `BRAND_KIND`, `PLATFORMS` or `MEDIA_KINDS`, and whether the
  project is standalone or beside syntek-author;
- what a generated project, or the machine it runs on, ends up doing;
- a concrete way to reach it and what it yields, not only a category name;
- the versions of Copier, the operating system, Python, ffmpeg and the coding agent, where they
  matter.

Reproduce it in an invented project. Never send an API key, an ElevenLabs voice ID, a private
recording, a piece's script or transcript, or anybody's personal data; if a key has leaked,
rotate it first.

## In scope

Code and configuration from this template that runs on the owner's machine or in their
repository:

- **`copier.yml`'s `_tasks` and `_migrations`**, which run under `--trust`. The five tasks run on
  a copy only: `git init`, `chmod +x` of the session hooks, the Git LFS tripwire, the warning
  about a syntek-author older than v0.6.0, which has no user guide, and, last, the `baseline` task, which runs
  `migrations/family-update.py` (D81). The migrations run on update. Anything that runs other
  than as documented, or that an answer can turn into a command.
- **The migration scripts in `migrations/`**, which run in the owner's project on update: the
  `.agents` handling of D76 (the 0.4.2 replacement of an `.agents -> .claude` link, and the hold
  and restore of an `.agents` link that leaves the project) touching anything but the link it
  names, or that link's target; the report-only `v0.6.0-how-to.py`, which must write nothing;
  and `family-update.py`, run last on every update and by the `baseline` task (D81, D84), which
  records each render under `refs/syntek-media/` inside `.git`, refreshes the family files
  `migrations/family-refresh.json` lists, adds that file's settings entries to
  `.claude/settings.json` and its two MCP servers to the MCP files, once each, and puts back
  the read-only `how-to/` guide. Any of them touching more than it says.
- **The standalone `.claude/settings.json` seed** (D13): an allow, ask or deny rule that lets a
  credit-spending ElevenLabs tool, `media.py voice remix run` or a Scrapling or code-review-graph
  tool it asks before go ahead without the promised prompt, or that allows more than the
  documentation says; its `Edit(/how-to/**)` deny that keeps the guide read-only (D84); and the
  hooks it registers: four handoff entries, the data-root guard and the guide guard (D80, D84).
- **The session hooks and the two family scripts** (D80): the three `.claude/hooks/*.sh`, which
  Claude Code runs in the owner's sessions, the guide guard `how-to-read-only.sh` among them
  (D84), the data-root guard, and `.claude/syntek-media-dataroot.py` and
  `.claude/syntek-media-permissions.py`, whose `--write` edits the coding agents' files. Their
  bytes are syntek-author's, vendored unchanged: a fix lands in syntek-author first and reaches
  this template with syntek-author's next release, so a report may go to either project.
- **The skills and rules that govern paid calls**: rules 03 Section 4 ('Credits: never spend
  unasked'), the ElevenLabs guard each credit-spending skill carries, and the two requests the
  toolkit sends itself, `voice remix run --approve-call` (D82) and Jev's
  `score run --approve-call` (D74).
- **Key handling.** `ELEVENLABS_API_KEY` and `TYPESAFE_API_KEY` come only from the owner's shell:
  a key written to a file, printed, logged or sent anywhere but its own service is in scope, as is
  the `claude mcp add` line the README and the message after a copy recommend.
- **The rule that keeps what Git ignores out of a session** (rules 06 Section 12): a skill or
  toolkit command that lists, searches or quotes an ignored file, such as a take or a render.
- **The toolkit, `template/toolkit/*.py`**: how it builds ffmpeg commands, resolves paths, renders
  local HTML in Chromium and makes its two paid requests. A read, write or command outside the
  project, or input that becomes a command.
- **The shipped agent-client configuration**: `.mcp.json`, `.agents/mcp_config.json`,
  `.codex/config.toml`, `.gemini/settings.json` and `opencode.json`, which declare two pinned MCP
  servers, Scrapling and code-review-graph, and never ElevenLabs (D80), and the `.agents/skills`
  link.
- **An audit** in `.github/scripts/` that would pass a render carrying any of the above.

## Out of scope

Report these to the project that maintains them:

- **Copier itself**, and the fact that `--trust` runs the template's tasks and migrations. That is
  by design and documented; read `_tasks` and `_migrations` in `copier.yml` before you generate,
  as with any template.
- **ElevenLabs** (the service and its MCP server's own code), **TypeSafe**, **Claude Code**,
  **Claude Design**, **Codex**, **Antigravity** and any other coding agent.
- **Upstream tools**: uv, Python, git, git-lfs, ffmpeg, Playwright and Chromium, WhisperX, Rhubarb,
  espeak-ng and GitHub Actions.
- **syntek-author's own files** in a project that has both templates: report them to
  [syntek-author](https://github.com/Syntek-Dev/syntek-author/security/advisories/new).

Also out of scope: a project you generated and then changed, which is yours; findings from an
automated scanner with no demonstrated effect on the template or on what it generates; and a stale
platform fact in `template/toolkit/data/platforms.toml`, which is an ordinary bug report.

## What to expect

syntek-media is maintained by a small studio alongside client work, so we handle reports on a
best-effort basis. We will acknowledge your report. Beyond that we make no fixed promise of
timescales, but we will look into it, tell you what we conclude (including when we decide
something is not a vulnerability, and why), and keep you informed while a fix is prepared. We do
not offer a bug bounty. GitHub adds you to the advisory's credits when you report; accept or
decline the credit there, or tell us if you would rather not be named.

## Disclosure

A confirmed vulnerability is fixed in a new release and disclosed through a
[GitHub security advisory](https://github.com/Syntek-Dev/syntek-media/security/advisories) on
this repository once that release is out, with an entry in [`CHANGELOG.md`](CHANGELOG.md). Please
keep the details private until the advisory is published.

## How a fix reaches a project

- **Template-owned files** (the rules, the skills, the toolkit, the guides and the workflows)
  arrive with the update, on a branch, run with Git's housekeeping off (add the five
  `GIT_CONFIG_*` variables the README's [Updating a project](README.md#updating-a-project) gives):
  `uvx --python '>=3.14' copier update --trust -a .copier-answers.syntek-media.yml`.
- **Copier never renders copy-only shared files and seeds on update** (D11), and
  `.claude/settings.json` is one of them. Since 0.6.0 the update script, on Python 3.14 or later,
  refreshes the family files `migrations/family-refresh.json` lists where the owner never changed
  them, and adds the settings entries and MCP servers it lists, once each, never one the owner
  removed after it was committed (D81). Anything else still needs a hand edit: the advisory and
  `CHANGELOG.md` give it, and where it can, `python3 toolkit/media.py check --setup` reports the
  missing line. Release 0.4.4 did this for its two `voice remix run` ask rules.

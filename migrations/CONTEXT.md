# CONTEXT.md — migrations/

The scripts `copier update` runs when a project crosses a release that moved something an author, or a shared path, holds.
Copier only tracks what it generated: a renamed folder takes its governance pair to the new place and leaves the author's work behind, and a copy-only shared path (D11) is never touched by an update at all, so a release that must change one can reach it only here.
A migration acts where exactly one result is correct and reports everything else.
Nothing here ships: `_subdirectory: template` keeps this folder out of every generated project, and `copier.yml` runs each script from the template clone through `_copier_conf.src_path`.

## Directory Tree

```text
migrations/
├── CONTEXT.md                  ← this file
├── CLAUDE.md                   ← operating rules for writing a migration
├── agents-outside-link.py      ← every update: an .agents link outside the project held aside and restored (D76; family-shared, vendored, D85)
└── v0.4.2-agents-folder.py     ← .agents -> .claude link → real .agents/ folder (D76)
```

## What's here

- `agents-outside-link.py` — **every brand kind, every update; the one script not keyed to a release.** Copier refuses any destination that resolves outside the project before it reads `_exclude` (Copier 9.17.1), so where `.agents` is a link to a folder outside the project, the files under `.agents/` stop every update. Two unversioned entries, first in `_migrations` and between syntek-author's `# BEGIN`/`# END family-shared migrations (D48)` markers, run it with `_copier_python`, the interpreter running Copier: `hold` at `_stage == 'before'` renames only such a link to `.agents.syntek-held` and prints the hand fix ('By hand' below) before the render, and where the held name already stands beside `.agents` moves nothing and says what to do; `restore` at `_stage == 'after'`, declared before the v0.4.2 entry, renames it back where `.agents` is absent, removes the held link where an identical `.agents` link already stands, and otherwise moves nothing and prints the hand fix for what stands at `.agents`. A stage that fails moves nothing more, and prints the hand fix where a link is held and otherwise says that nothing is held; no stage, or an unknown one, prints its usage line. Net change zero; the link's target is never touched; standard library only; each stage always exits `0` (`--self-test` exits `1` when a probe fails). `--self-test` runs both stages and the printed fix in temporary folders, and `--help` prints its docstring. The docstring asks for Python 3.11 or later, but the script runs on the interpreter running Copier, which Copier 9.12.0, the floor, allows to be 3.10: it parses under 3.10 and its `--self-test` passes there (D85). It is family-shared (syntek-author D48): media vendors it and its `_migrations` block byte for byte from a syntek-author release tag, first its `v0.5.0` (D85), so it names no template and no decision number, and neither is ever edited here (`shipped-seeds.sh` checks 21 and 22 pin both). D11's second, transient exception. An update that stops between the stages leaves the link held, and the next update refuses the changed tree until the link is put back by hand. A copy runs no migration: its hand recipe is in the bridge and `README.md`.
- `v0.4.2-agents-folder.py` — **every brand kind.** Releases 0.3.0 to 0.4.1 shipped `.agents` as a link to `.claude`, which makes every sandboxed Codex command fail (D76). Only where `.agents` is a symbolic link whose target is exactly `.claude` or `.claude/`, it builds the folder beside the link, swaps it in, links `.agents/skills -> ../.claude/skills`, and moves `.claude/mcp_config.json` to `.agents/mcp_config.json` where that path is free. Everything else is left and reported, with every tracked line that still describes the old layout. Standard-library Python 3, idempotent, never deletes author content, always exits `0`; `--help` prints its header. D11's first stated exception: media changes a shared path only here and, transiently, through `agents-outside-link.py`.
- **How each runs.** One `_migrations` entry per script in `copier.yml`, keyed by `version:` and run at `_stage == 'after'`, from the project root; the one exception is `agents-outside-link.py`, whose two unversioned entries run at both stages of every update. Copier runs a versioned entry only when the update crosses its version, read from the template's git tags; an update to an untagged `HEAD` still numbered below it does not, and no migration ever runs on `copier copy`.
- **By hand.** The update's clone of the template is deleted when the update ends, so each script ends by printing the command that clones the release from the source in the answers file and runs it again; `agents-outside-link.py` needs no clone, and prints its hand fix instead, which the README and the bridge give in these words: If an update stops before it ends (a refused answer, Ctrl-C at a question, or Copier failing as it cleans up after the render), the link stays held as `.agents.syntek-held`, and the next update refuses the changed tree; where the link is committed and the update stopped after its render, Copier has already put an identical `.agents` link back. Put the link back from the project root, in a POSIX shell (Terminal on macOS and Linux, Git Bash on Windows; never PowerShell's `rm`), before anything else, and before discarding the stopped update with `git reset --hard` and `git clean -fd`, which would delete a held link Git does not track. First check what stands at `.agents`: `ls -ld .agents .agents.syntek-held`. Where it shows no `.agents.syntek-held`, nothing is held: stop here and change nothing. Where `.agents` is a link (its line shows `->`), remove that link alone with `rm .agents` (never `rm -r`, never a trailing slash); where it is a folder or a file, move it aside to a name nothing holds yet (`ls -ld .agents.from-update` finds nothing) with `mv .agents .agents.from-update` (no trailing slash), which holds what the update wrote (check it, and delete nothing in it that is yours). Then, once `ls -ld .agents` finds nothing, run `mv .agents.syntek-held .agents` (no trailing slash). Never run that `mv` while `.agents` stands: it would put the held link inside it, and inside the folder outside the project where `.agents` is a link. Then update again; where `git status` still shows changes (a stop after the render), discard the stopped update first: run `git clean -n -d`, a dry run, move out of the project anything of yours it lists, then `git reset --hard && git clean -fd`. Where the held link was committed beside an identical `.agents` link, the next update moves nothing, says so, and asks you to remove the held link (`rm .agents.syntek-held`), commit, and update again.
